  ---
  What An Ensemble Architecture Would Look Like

  The insight is that Claude's decision space is a distribution, not a point. Every time we run /trade-decision, we're
  sampling once from that distribution. We should be sampling multiple times and using the variance.

  Layer 1: Decision Ensemble (Cheap, Build First)

  For every trade decision, run 3 independent Claude sessions with the same market data but:
  - Different system prompts (one conservative, one aggressive, one contrarian)
  - Or the same prompt at temperature > 0

  Then:

  If 3/3 agree → HIGH CONFIDENCE → full position size
  If 2/3 agree → MODERATE → 60% position size
  If 1/3 or 0/3 → LOW / DISAGREEMENT → no trade, flag for review

  The disagreement itself is a signal. When the ensemble splits, it means the decision is on a knife-edge — exactly when
   you should be smallest.

  This is 3x the token cost per decision. At 2 decisions/day, it's maybe $15-20/day extra. Trivial vs the portfolio
  value.

  Layer 2: Shadow Portfolios (Medium Effort)

  Maintain 3-5 virtual portfolios, each with an independent Claude "personality":

  - Portfolio A: Current system (thesis-driven, hold discipline)
  - Portfolio B: More aggressive (higher conviction thresholds, bigger positions)
  - Portfolio C: Contrarian (explicitly challenges consensus, looks for thesis fatigue)
  - Portfolio D: Regime-only (no individual thesis, just macro regime + ETFs)
  - Portfolio E: Statistical-only (only trades with MCPT-validated signals, ignores theses)

  Same starting capital, same data feeds, independent decisions. After 30-60 days, you know:
  - Which decision style has better Sharpe
  - Where they agree (robust signals) vs disagree (uncertain)
  - Whether the thesis approach actually adds alpha over simple regime positioning
  - The variance of outcomes — which tells you how much of your result was luck

  How To Measure It

  The meta-question: how do you evaluate which ensemble configuration works best?

  Decision divergence score: For each trade, measure the entropy of the ensemble's decisions. Track whether low-entropy
  decisions (consensus) outperform high-entropy decisions (disagreement). If they do, the ensemble is adding
  information.

  Regret analysis: For each position, compute what the portfolio would look like if we'd followed each ensemble member
  independently. The member with lowest regret over a 30-day window gets higher weight in the next period. This is
  essentially online learning over portfolio managers.

  Thesis half-life: Measure how long a thesis survives independent re-evaluation. If 3/3 fresh sessions confirm it after
   30 days, it's robust. If it degrades to 1/3 agreement, it was path-dependent. Track thesis half-life as a system
  health metric.

  ---
  What The Meta-Observer Actually Does

  This is the important part. It's not a capital allocator. It's a system improvement engine.

  It reads all three instances and asks:

  1. Where did they converge?

  If all three independently created an Iran War Energy thesis and went long XLE/SLB/HAL within the first week, that's a
   robust signal from the system. The thesis construction process reliably identifies this dislocation. That part of
  Athena works.

  2. Where did they diverge?

  If Instance 1 has KBR but Instances 2 and 3 don't, KBR was path-dependent — some session happened to see a specific
  headline, created a thesis, and conviction accumulated. The meta-observer flags this: "KBR is in 1/3 instances. Thesis
   construction for defense services is unreliable. Investigate why."

  If Instance 1 has CF at 96% conviction, Instance 2 has it at 82%, and Instance 3 has it at 71%, the true conviction is
   somewhere around 83% ± 12%. The system's point estimate of 96% is overconfident — confirmed by empirical variance
  across instances, not just calibration math.

  3. Which decisions led to better outcomes?

  After 30 days, Instance 2 is up 12%, Instance 1 is up 8%, Instance 3 is up 5%. The meta-observer diffs their decision
  histories:
  - Instance 2 entered tankers 3 days earlier (caught the VLCC spike)
  - Instance 2 never bought KBR (avoided the -13% drag)
  - Instance 2 sized CF at 8% vs Instance 1's 7% (slightly more aggressive on fertilizer)

  These are specific, actionable findings about the decision process that you can't get from running one instance.

  4. What changes to Athena itself?

  This is the feedback loop. The meta-observer produces patches to the core system:
  - "The trade-decision skill should weight fertilizer news higher in the morning briefing — Instance 2 caught the urea
  spike because it prioritized commodity prices over general news"
  - "The conviction velocity threshold for adds should be +1.5pp/day not +2pp/day — Instance 2's faster response
  captured more alpha"
  - "The adversarial agent should challenge single-instance theses more aggressively — positions held by only 1/3
  instances averaged -4.2% vs +7.8% for 3/3 consensus positions"

  These improvements go into the shared CLAUDE.md, shared skills, shared codebase. All three instances get better
  simultaneously. Then you measure whether the next 30-day period shows tighter convergence. If it does, the system is
  learning. If divergence stays the same, the stochastic component is irreducible and you need the ensemble permanently.

  ---
  The Measurement Framework

  What you're building is essentially a Monte Carlo on the decision process itself, with live money. The metrics that
  matter:

  Convergence Rate: What fraction of decisions are made by all 3 instances? This should increase over time as the system
   improves. If it plateaus at 60%, that means 40% of decisions are inherently path-dependent and the ensemble is
  providing permanent value.

  Divergence-Weighted Returns: Do positions held by 3/3 instances outperform positions held by 1/3? If yes, consensus is
   informative. If no, independence doesn't predict quality and you need a different aggregation method.

  Thesis Discovery Overlap: Do the three instances independently discover the same theses? Track Jaccard similarity of
  thesis sets over time. Low overlap = the thesis creation process is noisy. High overlap = it reliably identifies
  structural dislocations.

  Calibration Comparison: Which instance has the best prediction accuracy? Is it consistently the same one, or does it
  rotate? If it rotates, calibration is noisy. If one is consistently best, study its decision chain for why.

  Improvement Velocity: After the meta-observer pushes a change to the core system, how quickly do the three instances
  converge on the new behavior? Fast convergence = the change was clear and effective. Slow convergence = the change was
   ambiguous or overridden by path-dependent context.
